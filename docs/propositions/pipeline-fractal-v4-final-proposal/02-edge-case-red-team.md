# 02 - Edge Case Red Team

Status: red-team input for Cycle 01 final proposal

## Decision Rule

The final proposal must fail closed when the RMS cannot prove state, risk,
runtime capability, evidence freshness, or checkpoint resolution.

Fail-open is allowed only for T/F work when the missing control is non-blocking,
is traced, and the final state is `DONE_WITH_GAPS`, never `DONE_VERIFIED`.

| Edge case | Failure mode | Expected handling | Blocking decision |
|---|---|---|---|
| Non-dev run | A `research`, `architecture`, or `planning` run produces decisions that later get treated as pipeline evidence even though `pipeline_activation=inactive`. | Keep `harness_machine.status=NOT_ACTIVE`. Allow read/analysis output, but mark produced artifacts as `candidate_evidence` until an active run imports them through Cadrage or Conception with a transition event. | Block macro-cycle handoff if inactive artifacts are used as authoritative evidence without import. |
| Long-lived Run | `RUN` is treated like a terminal phase, so operations either never close or close too early before enough stability evidence exists. | Model Run as long-lived. Emit `RUN_SAMPLE_READY` into Apprentissage without claiming operations are complete. Keep operational monitoring/runbook obligations alive after delivery closure. | Block `DONE_VERIFIED` if Run evidence is required by risk class and only a release handoff exists. Allow `DONE_WITH_GAPS` only for non-E/C residual gaps. |
| Critical risk | A C-class route is allowed to proceed under `auto_decision` or hidden bypass because evidence looks complete. | Force pairing or explicit human-visible validation. Require maximal evidence, independent review, rollback proof, and no unresolved critical gaps. | Block all bypass. Block `DONE_VERIFIED` if human checkpoint, independent review, or rollback evidence is missing. |
| Runtime missing / fail-open | Hooks, stop gates, or pre-tool enforcement are absent and the adapter silently continues. | Capability discovery must run before active execution. For T/F, trace degraded enforcement and require post-run verification. For M, allow only if exhaustive post-run verification can compensate. For E/C, missing hard gates default to `BLOCKED_RUNTIME_MISSING`. | Block M+ when required enforcement is absent and no declared fallback exists. Block E/C by default on fail-open runtime. |
| Stale evidence | Tests, reviews, runtime capability, or risk classification predate the latest diff or route change. | Evidence Set must track freshness against last state-changing event. Any mutation to scope, risk, runtime binding, or touched files invalidates dependent evidence. | Block `DONE_VERIFIED` on stale evidence. Rerun or downgrade to `DONE_WITH_GAPS` only when risk permits. |
| Subagent disagreement | Reviewer, threat-modeler, test-writer, or evidence-collector outputs conflict, or one lane claims approval while another reports blockers. | Parent RMS, not subagents, arbitrates. Mark evidence `conflicted`, preserve both outputs, and route to reviewer/arbiter or human checkpoint depending on risk. | Block final state while evidence is conflicted. For E/C, require human or independent review resolution. |
| Skill drift | Installed skill copy diverges from monorepo source, trigger keywords collide, or a skill starts owning state it should only request through MCP. | Skills are portable procedures only. The MCP state kernel owns canonical state, guards, evidence, and convergence. Skill version/source hash should be checked at session start or install sync. | Block auto-invocation for drifted core skills. Block state mutation from skills unless routed through MCP/kernel APIs. |
| Book drift | Durable manuals/books contradict executable guards, risk matrices, or current state-machine rules. | Books are explanatory/contracts, not runtime authority. Treat them as reference inputs that must be reconciled via Apprentissage or design update. | Block implementation planning if a book claims a different safety/risk rule than the MCP/kernel registry. Do not block T/F execution on non-authoritative prose drift if runtime guards are clear. |
| MCP outage | `harness-state` MCP is unavailable, slow, or returns partial state, while hooks/files still exist. | Enter file-only degraded mode only for reads and append-only logs. Do not mutate canonical state unless the kernel has a declared local transaction fallback. Log `MCP_UNAVAILABLE`. | Block state transitions requiring canonical mutation. Block M+ final verification if the MCP outage prevents Evidence Set or guard evaluation. |
| Loop convergence | The run cycles through validation/build or design options without fresh evidence, but max attempts has not yet fired. | Convergence must be sampled by evidence delta, risk delta, defect delta, and scope stability. A new iteration needs a distinct progress hypothesis and expected signal. | Block repeated attempts without new hypothesis. Emit `LOOP_DETECTED` or checkpoint when oscillation repeats without evidence gain. |
| User checkpoint ambiguity | User says "ok", "continue", or gives a vague answer where policy requires explicit approval or risk acceptance. | Checkpoints must name the decision, risk class, residual gaps, and allowed next action. Ambiguous assent may unblock low-risk continuation but not E/C approval. | Block E/C gates until explicit approval is recorded. Block destructive or irreversible action if checkpoint scope is unclear. |
| Evidence after closure | A late subagent result, CI result, or runtime error arrives after `pipeline_activation=closed`. | Closed runs are immutable except append audit. Late evidence can open an audit record or seed Apprentissage, not rewrite final state silently. | Block mutation of final state. Require a new correction/reopen event if the late evidence invalidates the closure. |
