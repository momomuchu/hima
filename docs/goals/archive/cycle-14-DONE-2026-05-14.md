## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **Book route is explicit** - the review cites the relevant `07-build/code-quality-maintainability-excellence-book` route and explains why adjacent release/security/architecture decisions are out of scope.
2. **Local evidence is primary** - findings are grounded in the actual Cycle-13 code, tests, docs, and verification outputs, not generic maintainability advice.
3. **Source limits are named** - OpenHands source correction and otherskill book guidance are treated as scoped signals, not broad release or architecture approval.
4. **Maintainability risks are triaged** - any issue is classified as fix-now, defer-with-owner, or no-action, with concrete file references.
5. **Diff stays narrow** - code edits are limited to low-risk clarity and boundary fixes in the skill installer surface.
6. **Behavior remains locked** - schema gating, dry-run no-write behavior, path safety, precedence, unsafe-name rejection, and no-org default resolution remain covered.
7. **Truth surfaces align** - the new review, master goal, short-term goal, and docs index do not contradict Cycle-13 DONE evidence.
8. **Verification passes** - focused skill install tests, full core tests, `corepack pnpm lint`, `corepack pnpm docs:index`, and `corepack pnpm build` are green.
9. **Inventory stays truthful** - `core-file-to-context.csv` still matches `packages/core/src`.
10. **Saturation check** - a critic pass tries to find hidden behavior drift, stale docs, unowned maintainability debt, insufficient tests, and adjacent-scope overclaim. Any material finding reopens the cycle.
