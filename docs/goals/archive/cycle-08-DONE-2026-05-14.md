## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **Event vocabulary is explicit** — each C4 event has a named context owner and payload contract.
2. **Events reach the event log** — current runtime paths that claim an event append it through `events-log.ts`.
3. **Ledger compatibility remains intact** — event-log changes do not break hash-chained ledger verification where ledger entries are expected.
4. **Payload ownership is respected** — Run, Cycle, Gate, Evidence, Skill, and Subagent data are not collapsed into a generic event blob without owner context.
5. **Tests prove behavior** — focused tests cover event names, payloads, log append, and ledger compatibility.
6. **Risk promotion is not overclaimed** — `RiskClassPromoted` is emitted for the existing `enterDevelopment` project-root risk-promotion path and is not claimed for demotion or no-change updates.
7. **Truth surfaces align** — C1 map/CSV and the C4 implementation note identify event ownership consistently.
8. **Verification passes** — `corepack pnpm --filter @harness/core test -- --runInBand`, `corepack pnpm lint`, and `corepack pnpm build` are green.
9. **Saturation check** — a critic pass tries to find generic event names, missing event-log writes, ledger drift, owner collapse, stale master-plan truth, and C5-C7 leakage. Any material finding reopens the cycle.
