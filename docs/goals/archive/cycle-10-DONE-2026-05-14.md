## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **Invariant is explicit** — the Run aggregate names the always-valid condition it enforces, including no `DONE_VERIFIED` without sufficient evidence.
2. **Invalid state is rejected before persistence** — aggregate-owned writes cannot save inconsistent state/route/risk/finalization combinations, and finalization cannot persist `DONE_VERIFIED` without sufficient evidence.
3. **Existing valid flows remain compatible** — transition, enter-development, close-run, evidence, and hook tests remain green or are updated only where behavior is intentionally tightened.
4. **Ownership stays clean** — Cycle legality, Gate policy, Evidence event taxonomy, and repository storage mechanics remain outside the invariant guard.
5. **Tests prove behavior** — focused tests cover both rejected invalid states and valid aggregate persistence.
6. **No broad refactor leak** — C6 does not implement C7 aggregate-style test migration.
7. **Truth surfaces align** — C1 map/CSV and the C6 implementation note identify invariant ownership consistently.
8. **Verification passes** — `corepack pnpm --filter @harness/core test -- --runInBand`, `corepack pnpm lint`, and `corepack pnpm build` are green.
9. **Saturation check** — a critic pass tries to find invariant holes, misplaced business policy, stale truth surfaces, compatibility drift, and C7 leakage. Any material finding reopens the cycle.
