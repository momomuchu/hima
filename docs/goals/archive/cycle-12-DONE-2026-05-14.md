## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **Locked fields are executable** - the schema requires `name`, `version`, `type`, `triggers`, `expected_outputs`, `requires_tools`, `fallback_for_toolsets`, and `description`.
2. **Type is closed** - `type` accepts only `task` or `knowledge`.
3. **Unknown fields are rejected** - frontmatter parsing is strict enough that schema drift cannot silently enter installed skills.
4. **Arrays are real arrays** - list fields reject scalar strings and require non-blank string entries.
5. **Parse-time API is available** - the module exposes a small parse/validate surface usable by future installers without duplicating Zod logic.
6. **Scope stays narrow** - no D-S1 install convention, HARV-10 4-tier resolver, hook wiring, MCP server work, or broad catalog migration is implemented in this cycle.
7. **Truth surfaces align** - the Stream D implementation note and master checklist accurately reflect what was and was not delivered.
8. **Verification passes** - focused schema tests, full core tests, `corepack pnpm lint`, `corepack pnpm docs:index`, and `corepack pnpm build` are green.
9. **Inventory stays truthful** - `core-file-to-context.csv` matches `packages/core/src` after any new source file is added.
10. **Saturation check** - a critic pass tries to find schema looseness, extra-field drift, install-scope leakage, missing exports, stale docs, and insufficient negative tests. Any material finding reopens the cycle.
