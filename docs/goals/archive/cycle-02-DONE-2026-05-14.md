# Short-Term Goal — Cycle 02: Apply analysis-discovery excellence-book to hima (real research pass)

## 1. Why this cycle, why now

The previous excellence-book audit (W0–W5 in `.planning/excellence-audit/EXCELLENCE-AUDIT-REMEDIATION.md`) was a **desk audit** — it compared book recommendations against existing hima docs but did NOT do the kind of research that a real discovery pass requires. Specifically, it missed:

1. **Per-coding-agent adapter coverage analysis** — hima claims Claude Code + Codex + Hermes adapters, but no audit exists of what the *market* looks like (Cursor, Aider, OpenHands, Windsurf, Devin, AGENTS.md, Augment Intent, Goose, Cline, Kiro, Continue, Roo Code, Zed Edit, JetBrains AI Assistant, Cody, Copilot Agents, etc.) and where hima's adapter gaps actually are.
2. **Existing-harness landscape comparison** — what do other coding-agent harnesses / orchestration frameworks look like in 2026? What primitives have they shipped that hima doesn't? Does hima's differentiator hold up to scrutiny? `verification-02-competitive-matrix.md:20` already conceded the moat is narrower than originally claimed — but never said by how much, against whom, on which axes.
3. **Real go/no-go gate research** — does the engineering gate in `05-gates-policy-spec.md` match what state-of-the-art harnesses actually do? Or is hima reinventing primitives that already have community-accepted shapes?

This cycle exists to test **whether the excellence books are actually applicable in practice** when applied with real research, not just text-vs-text comparison. It is simultaneously a hima improvement cycle AND an excellence-book validation cycle.
