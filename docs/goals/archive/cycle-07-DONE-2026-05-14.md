## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **Value-object boundaries exist** — `RiskClass`, `SubPhase`, `OperatingMode`, and `GateType` have named construction/validation APIs.
2. **Invalid values are rejected** — tests prove invalid string values fail at the boundary.
3. **Public constants remain stable** — existing arrays/enums used by schemas, gates, and tests keep their external shape unless all call sites are updated.
4. **Ownership is explicit** — the C3 note maps `RiskClass` to Gate, `SubPhase` to Cycle, `OperatingMode` to Run/Gate coordination, and `GateType` to Gate.
5. **No broad refactor leak** — C3 does not start C4-C7 implementation.
6. **File inventory is current** — C1 CSV includes new value-object files.
7. **Verification passes** — `corepack pnpm --filter @harness/core test -- --runInBand`, `corepack pnpm lint`, and `corepack pnpm build` are green.
8. **Saturation check** — a critic pass tries to find weak value-object boundaries, broken public compatibility, misplaced ownership, and stale master-plan truth. Any material finding reopens the cycle.
