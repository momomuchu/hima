## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **PreToolUse contract is explicit** - the implementation note states which runtime payload fields are normalized and how decisions are returned.
2. **Write-zone enforcement is proven** - tests show a PreToolUse write outside allowed zones returns a blocking or warning gate verdict consistent with current risk/policy semantics.
3. **Planning-state failure stays fail-closed** - missing or unreadable planning state blocks instead of silently allowing tool execution.
4. **Secrets stay redacted** - tool input previews and gate reasons do not persist known secret patterns.
5. **Dry-run is safe** - hook dry-run/equivalent does not append events or mutate planning state.
6. **Scope stays narrow** - no SessionStart, Stop, UserPromptSubmit, PostToolUse, SubagentStart policy, PreCompact/PostCompact, MCP, prompt, skill-lint, or migration work lands.
7. **Truth surfaces align** - implementation note, master checklist, and current short-term goal describe exactly what landed and what remains.
8. **Verification passes** - focused hook tests, full core tests, `corepack pnpm lint`, `corepack pnpm docs:index`, and `corepack pnpm build` are green.
9. **Inventory stays truthful** - `core-file-to-context.csv` matches `packages/core/src` if source files change.
10. **Saturation check** - a critic pass tries to find hook overclaim, fail-open behavior, redaction gaps, dry-run mutation, stale docs, and insufficient negative tests. Any material finding reopens the cycle.
