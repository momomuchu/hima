moving Cycle-owned legality. The remaining C2 work is to remove stale "free service" ambiguity
around transition ownership while keeping target resolution, validation, and DoR/DoD governance

## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **Cycle boundary is explicit** — target resolution, validation, state transition calculation, and DoR/DoD governance live behind a Cycle-owned boundary.
2. **Run boundary remains orchestration only** — `RunAggregate.transition` coordinates persistence and event/ledger side effects but does not own transition legality.
3. **Compatibility is deliberate** — any remaining `state-machine/transition.ts` exports are compatibility exports or clearly Cycle-owned, not a second orchestration service.
4. **Public API stays stable** — `requestTransition` callers receive the same success/failure shapes, governance payloads, and persisted state effects.
5. **Tests prove behavior** — request-transition, transition, state-machine sequence, and DoR/DoD governance tests are green after the boundary cleanup.
6. **Truth surfaces align** — C1 CSV/map and C2 implementation note identify Run and Cycle ownership consistently.
7. **Verification passes** — `corepack pnpm --filter @harness/core test -- --runInBand`, `corepack pnpm lint`, and `corepack pnpm build` are green.
8. **Saturation check** — a critic pass tries to find Cycle logic moved into Run, duplicate transition owners, stale compatibility exports, public API drift, and stale master-plan truth. Any material finding reopens the cycle.
