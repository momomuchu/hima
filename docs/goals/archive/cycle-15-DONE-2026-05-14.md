## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **Book route is explicit** - the packet cites the relevant `09-quality-release-run` quality/review/release route and separates quality evidence from maintainability or architecture claims.
2. **Evidence inventory is complete for this slice** - focused tests, full core tests, lint, build, docs index, inventory, post-tool dry-run, and critic evidence are listed with interpretation limits.
3. **Release limits are named** - the packet does not claim public release readiness, adapter runtime exposure, hook coverage, skill linting, or bulk migration.
4. **Test portfolio is assessed** - each D-skill behavior from Cycle 13/14 maps to at least one focused test or an explicit deferred gap.
5. **Rollback/recovery is described** - the installer/resolver changes have a practical rollback or disable path for future integration.
6. **Deferred gaps have owners** - runtime adapter exposure, parser variations, hook integration, skill lint, and bulk migration are routed to future cycles or adjacent books.
7. **No behavior drift unless justified** - added tests remain inside the D-skill installer/resolver surface.
8. **Verification passes** - focused skill install tests, full core tests, `corepack pnpm lint`, `corepack pnpm docs:index`, and `corepack pnpm build` are green.
9. **Inventory stays truthful** - `core-file-to-context.csv` still matches `packages/core/src`.
10. **Saturation check** - a critic pass tries to find release overclaim, missing test evidence, stale truth surfaces, unowned deferred gaps, and hidden behavior drift. Any material finding reopens the cycle.
