# Short-Term Goal - Cycle 23: Stream D MCP Governance Tools

## 1. Why this cycle

Cycle-22 resolved the D-H7 sourcing risk without speculative runtime code. The next master checklist
block is D-MCP: externally callable governance tools for non-HIMA agents. The current MCP server
already exposes many `rms.*` and legacy `harness:*` tools, but the master D-MCP checklist still names
the external HIMA tool contract: `hima_evaluate_completion`, `hima_classify_risk`,
`hima_record_evidence`, and `hima_query_compliance`.

This cycle must reconcile that truth surface with executable MCP behavior. The work should prefer
small aliases or thin wrappers over new policy logic, unless the current server cannot satisfy the
named contract.

## 3. DONE criteria (saturation-enforced)

This cycle reaches `status: DONE` when ALL of:

1. **Named D-MCP surface exists** - D-M1 through D-M4 are either executable MCP tools or explicitly mapped to existing canonical `rms.*` tools with compatibility names.
2. **No duplicate policy fork** - wrappers call the same core services as existing MCP tools and do not create a second risk/evidence/gate/compliance implementation.
3. **Write-side safety holds** - `hima_record_evidence` keeps root confinement, redaction, canonical evidence-key/status validation, and cannot forge policy events.
4. **Read-side query is scoped** - `hima_query_compliance` reads only the current project/run compliance surface and does not expose arbitrary filesystem paths.
5. **Spec and executable surface align** - `docs/conception/11-mcp-tools-spec.md` matches `getMcpToolSurface()` and tool schemas.
6. **Truth surfaces align** - architecture note, master checklist, current short-term goal, and docs index state exactly what landed and what remains.
7. **Verification passes** - focused MCP tests, full core tests if core code changes, `corepack pnpm lint`, `corepack pnpm docs:index`, and `corepack pnpm build` are green.
8. **Inventory stays truthful** - `core-file-to-context.csv` matches `packages/core/src` if source files change; no core inventory change is needed for MCP-only files.
9. **Saturation check** - a critic pass tries to find duplicate policy semantics, unsafe writes, stale docs/spec mismatch, missing D-M alias coverage, missing negative tests, and incomplete end-to-end MCP evidence. Any material finding reopens the cycle.
