# Short-Term Goal — Cycle 02c: Tiered-cascade routing + keyword registry

## 1. Why this cycle

Cycle-02b made the state machine transitionable and auditable. The next blocker is routing: hima still has AUTO-INVOKE as prose and an operational catalog, but no code-side typed keyword registry or deterministic cascade that can route a prompt before spending LLM tokens.

This cycle implements SYNTHESIS pattern #2 + #13:

1. **Typed keyword registry** — promote AUTO-INVOKE prose into a flat, testable registry with priorities.
2. **Tiered cascade router** — route by regex, state, keyword, then LLM-fallback descriptor. Only the last tier is a token-spending fallback; the first three are deterministic.
3. **Runtime observability** — every routing decision can be stored through the cycle-02b event log surface.

## 2. Deliverables

| # | File | Content |
|---|------|---------|
| C2C-1 | `packages/core/src/catalogs/keyword-registry.ts` | Typed flat-array keyword registry. Entries include id, target skill, patterns/keywords, priority, optional gate/cycle/risk/mode filters, and provenance/source. |
| C2C-2 | `packages/core/src/catalogs/router-cascade.ts` | 4-tier router: regex override -> state route -> keyword registry -> LLM fallback descriptor. Deterministic tiers return a route without model calls. |
